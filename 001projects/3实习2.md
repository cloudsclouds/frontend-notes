# Radix UI + Tailwind CSS
Radix UI 是一个专注于可访问性和交互逻辑的无样式 React 组件库。
它提供了像对话框、下拉菜单、标签页等常见组件的底层功能，比如键盘导航、焦点管理这些无障碍特性，处理好了组件的交互逻辑，但不自带样式，需要结合 Tailwind 的原子类快速拼接样式，比手写 CSS 更快，还能避免样式冲突。

Tailwind CSS 是原子化 CSS 框架，特点是把 CSS 属性拆成小类名，比如 “flex”“mt-4”“text-blue-500”，直接在 HTML 标签里组合类名就能写样式，不用单独写 CSS 文件。
和普通 CSS 比，它不用费心取类名，开发速度快，而且样式不会冗余，因为类名是复用的。普通 CSS 需要定义类名，写具体属性，大型项目容易出现样式冲突或冗余代码。

# 首屏优化
## 1. 背景介绍
针对用户首次加载时间页面过长，发现首屏 FCP 和 LCP 指标较差、js 体积过大等问题，设计了分阶段渲染策略。
首先，将页面拆分为关键路径和非关键路径，首屏只加载核心的总览信息，而将复杂的详情表格通过 React.lazy 和 Suspense 进行按需加载，结合 Vite 自动分包机制，避免阻塞主要线程。同时，还利用浏览器空闲时间，对后续 Tab 资源进行预加载。
最终显著降低了首屏耗时，FCP 和 LCP 通过浏览器自带的 LightHouse 面板可以看到指标有明显提升。

## 2. 这个首屏优化项目的场景是什么？
这是一个看板类页面，先把页面拆成关键路径和非关键路径。
- 关键路径包含顶部导航、核心总览卡片、主体骨架、首屏必要的 1 到 2 个基础接口。
- 非关键路径包含大表格、抽屉弹窗、图表模块，以及非首屏路由的详情页等内容。

## 3. 分阶段渲染具体是怎么做的？
第一阶段只渲染页面结构、筛选框架和核心总览数据，不挂载重要的表格和图表组件，先保证页面尽快可见、可交互。
第二阶段使用 `React.lazy` 和 `Suspense` 异步加载大表格，并补发对应异步请求，让用户看到首屏后再逐步补齐内容。
第三阶段利用 `requestIdleCallback`，在浏览器空闲时预热抽屉、图表组件和高概率会进入的下一个页面，同时配合 `queryClient.prefetchQuery(...)` 预取数据，减少后续切换等待。

## 4. 预加载是怎么做的？为什么不在首屏直接请求？
预加载是在主线程空闲时做的，本质是把“用户下一步大概率会点开的资源”提前准备好，而不是跟首屏抢资源。如果这些内容在首屏就一起加载，会影响 FCP 和 LCP；放到 idle 阶段做，更符合性能优先级。

# 权限体系与动态路由
## 1. 背景介绍
项目里角色存在差异，比如质控员、管理员、科室负责人看到的菜单和可操作按钮都不一样，这里基于 RBAC 做了一套统一的权限控制方案。

具体来说，后端会返回当前用户的角色标识、权限列表和可访问路由。前端在拿到这些数据之后，
1. 根据后端返回的权限路由数组，基于 `React Router` 的动态路由配置把用户有权限访问的页面注册进系统里。
2. 侧边栏菜单也是根据权限路由动态渲染，无权限的菜单直接隐藏，保证路由和菜单来源一致。
3. 按钮级权限通过自定义 Hook `usePermission` 实现，比如新增、编辑、审核、提交这些操作，根据权限点决定按钮是否渲染，点击时做二次校验，防止越权操作。

## 2. 为什么前端已经隐藏按钮了，还要做二次校验？
因为前端隐藏按钮只是体验层的控制，不是最终安全边界。用户权限可能在页面停留期间发生变化，或者前端状态过期，所以在点击时再校验一次，可以减少误操作和越权风险。最终真正的安全校验仍然要靠后端。

## 3. 员工正在 A 页面，临时被禁用权限，如何实时拦截？
这个场景分两种实现方式。
- 第一种是路由守卫加动态刷新路由。在全局守卫里，每次进入新路由都会重新请求后端最新权限，清空旧动态路由并重新注册。这样当该员工下次跳转页面时，守卫会检测到 A 页面无权限，直接拦截跳转 403。缺点是用户停留在 A 页面不动时，不会立即生效。
- 第二种是轮询权限接口，适合要求实时拦截的场景。前端定时请求权限接口，每次比对当前页面权限，一旦检测到权限被关闭，就立刻弹窗提示并强制跳转。为了减少性能损耗，页面失焦时会暂停轮询，页面激活再恢复。

# 病例质控审核
## 1. 背景介绍
这个组件要支持质控员对病例录音的人工审核评分，不同题的评分规则不一样，题型涵盖单选、多选、等级评分等。设计了 “外层容器 + 子组件” 的结构：
外层容器主要负责一些通用逻辑，比如后端规则转前端结构、总分计算、处理只读和编辑状态切换，是否需要回填历史记录；
内层再根据配置动态分发不同的评分子组件，比如单选、多选、等级评分都各自封装。
这样做的好处是，后面如果评分规则有调整，或者新增一种题型，优先改配置和局部组件就可以，不需要整块页面重复开发，复用性和可维护性会更好。
另外在复核场景下，复核员需要参考前两轮质控员的评分结果，也补了对应的查看和切换能力，方便在复核时对照不同人的评分记录。

## 2. “外层容器 + 子组件”具体是怎么分工的？
外层容器主要负责三件事。
- 第一，把后端返回的规则数据，比如模块下面有哪些子项、每个子项是什么评分方式、检查点有哪些、每个检查点扣多少分，转换成前端统一结构，比如统一成 `ruleId`、`maxScore`、`selectionMode`、`checkpoints` 这些字段。
- 第二，统一管理状态和分数，比如每一题当前得分、总分、只读态还是编辑态、是否需要回填历史记录。
- 第三，根据配置决定渲染哪一种子组件，比如 `single` 渲染单选卡片，`multiple` 渲染多选卡片，`level` 渲染等级评分卡片。

子组件本身只关心自己的交互，不关心整张评分卡怎么汇总。

容器给子组件的入参是标准化后的单题配置、历史回填值和禁用只读状态；子组件对外只抛分值变更回调，返回当前题 ID、单题得分和用户选择数据。

## 3. 历史回填和复核参考是怎么处理的？
外层会先把历史评分结果转成和当前题型一致的结构，再传给对应子组件做回显。复核场景下，还会保留前两轮质控员的评分结果供查看和切换，方便复核员横向对比。

# 语音输入与录音播放器
## 1. 背景介绍
封装了语音输入和录音播放器模块，主要是为了满足录音质检和病例审核场景下的使用需求。

这块录音能力，采集层基于浏览器原生 `getUserMedia` 和 `MediaRecorder`，但没有把整段录音一直攒在内存里，而是按固定间隔切成音频分片，同时把分片异步落到本地存储。这样做的核心目的，是提升长时间录音场景下的稳定性、可恢复性。

在波形可视化上，主要是基于原生 `WebAudio` 和 `Canvas` 方案。
录制实时波形：借助 `AudioContext` 解析麦克风实时流，提取 `PCM` 采样数据，通过 `Canvas` 动态绘制波形。
播放静态波形：播放前解码音频文件得到完整 PCM 数据，通过 `Canvas` 渲染全量波形图谱。

在播放器基础能力上，主要是基于原生 `Audio` 标签搭建播放器基础，通过 `requestAnimationFrame` 循环刷新播放时间，联动进度条实现进度实时同步。  
倍速播放通过修改 `playbackRate` 参数控制播放倍率，
断点续播通过缓存当前播放时间戳到页面状态或本地存储，再次打开自动跳转上次播放点位；

## 2. 录音采集是怎么做的？
先通过 `getUserMedia` 申请麦克风权限，拿到音频流后创建 `MediaRecorder` 开始录音。这里不是等录音结束后一次性生成一个大文件，而是让录音过程按固定间隔持续产出音频分片。

每次产生音频分片时，会先暂存在内存里，再异步写入 `IndexedDB`，等于做了一层“内存 + 本地存储”的双保险。
- 第一，避免整段录音一直堆在内存里。
- 第二，页面异常刷新，仍然可以从本地分片重新拼回完整录音。
- 第三，分片异步落库，不会明显阻塞主线程。

## 3. 为什么不用“录完再一次性生成整段文件”？
因为质检和审核场景下，录音时间可能比较长，一次性攒到结束再处理，内存压力更大，而且一旦页面异常中断，数据恢复会比较困难。分片方案更适合长时任务。

## 4. 结束提交时，录音是怎么停止的？
结束提交流程开始后，会先调用停止录音逻辑，让 `MediaRecorder` 停止采集，同时清理录音计时器、释放麦克风流，然后把已经采集到的音频分片组装成最终的 `Blob`。

## 5. 如果结束提交时部分数据丢了怎么办？
做了兜底策略：优先使用本地持久化的分片去合并，因为它更完整、更稳；如果本地分片异常拿不到，再退回使用内存里暂存的分片，尽量保证提交时仍能拿到完整录音。

## 6. 录音什么时候上传？
停止录音之后，前端会先确认有没有可用的录音文件；如果有，就把最终的 `Blob` 转成 `File` 上传到文件服务，拿到后端返回的文件 URL。上传成功后会回写到当前审核数据里；上传失败则记录失败状态，方便后续重试。

## 7. 你是怎么实现录音波形可视化的？
录音结束后先通过 `AudioContext` 解析音频文件，获取 PCM 采样数据。PCM 本质上是一组 `-1` 到 `1` 的音量值，会对数据进行抽样降采样，然后把时间映射到 X 轴、音量映射到 Y 轴，最后使用 `Canvas` 通过 `lineTo` 连线绘制音频波形。

## 8. 为什么这里用 Canvas，而不是用 DOM 或 SVG？
因为波形图点位很多，而且播放过程中可能需要高频刷新。用 DOM 节点渲染会非常重，SVG 在超多点位场景下也会有性能压力，`Canvas` 更适合这类连续、高频绘制任务。

## 9. 播放器的基础能力是怎么做的？
播放器本身基于原生 `Audio` 标签搭建，再结合 `requestAnimationFrame` 循环刷新播放时间，联动进度条实现进度实时同步。倍速播放通过修改 `playbackRate` 控制，断点续播则缓存当前时间戳到页面状态或本地存储中。

```ts
class AudioRecorderPlayer {
  private mediaStream: MediaStream | null = null;
  private mediaRecorder: MediaRecorder | null = null;
  private audioChunks: Blob[] = [];
  private audioUrl = '';
  private audio = new Audio();

  private audioContext: AudioContext | null = null;
  private analyser: AnalyserNode | null = null;
  private sourceNode: MediaStreamAudioSourceNode | null = null;
  private animationId = 0;

  constructor(private canvas: HTMLCanvasElement) {}

  // 1. 开始录音：申请麦克风权限，初始化 MediaRecorder 和波形分析器
  async startRecord() {
    // 获取麦克风音频流
    this.mediaStream = await navigator.mediaDevices.getUserMedia({ audio: true });

    // 创建录音器，浏览器会持续产出音频分片
    this.mediaRecorder = new MediaRecorder(this.mediaStream, {
      mimeType: 'audio/webm'
    });

    // 每次开始录音前都清空旧分片，避免串音
    this.audioChunks = [];

    // 录音分片回调：把每次产出的数据先缓存起来
    this.mediaRecorder.ondataavailable = (event) => {
      if (event.data.size > 0) {
        this.audioChunks.push(event.data);
      }
    };

    // 初始化实时波形分析
    this.initWaveAnalyzer(this.mediaStream);

    // 开始录音
    this.mediaRecorder.start();
  }

  // 2. 停止录音：拼接 Blob，转成可播放的 url，并清理录音流
  stopRecord(): Promise<File> {
    return new Promise((resolve, reject) => {
      if (!this.mediaRecorder) {
        reject(new Error('录音器未初始化'));
        return;
      }

      this.mediaRecorder.onstop = () => {
        // 把所有分片拼成一个完整音频文件
        const audioBlob = new Blob(this.audioChunks, { type: 'audio/webm' });

        // 给播放器使用的本地预览地址
        this.audioUrl = URL.createObjectURL(audioBlob);
        this.audio.src = this.audioUrl;

        // 转成 File，方便后续上传到服务端
        const file = new File([audioBlob], `record-${Date.now()}.webm`, {
          type: 'audio/webm'
        });

        // 停掉麦克风采集，释放设备占用
        this.mediaStream?.getTracks().forEach((track) => track.stop());

        // 停掉波形动画
        cancelAnimationFrame(this.animationId);

        resolve(file);
      };

      this.mediaRecorder.stop();
    });
  }

  // 3. 播放录音：直接复用原生 Audio 能力
  play() {
    if (!this.audioUrl) return;
    this.audio.play();
  }

  pause() {
    this.audio.pause();
  }

  // 4. 倍速播放：直接修改 playbackRate
  setPlaybackRate(rate: number) {
    this.audio.playbackRate = rate;
  }

  // 5. 断点续播：把当前播放时间保存起来，下次恢复
  saveProgress() {
    localStorage.setItem('record-progress', String(this.audio.currentTime));
  }

  restoreProgress() {
    const saved = localStorage.getItem('record-progress');
    if (saved) {
      this.audio.currentTime = Number(saved);
    }
  }

  // 初始化实时波形分析
  private initWaveAnalyzer(stream: MediaStream) {
    this.audioContext = new AudioContext();

    // 把麦克风流接入 Web Audio
    this.sourceNode = this.audioContext.createMediaStreamSource(stream);

    // AnalyserNode 用来提取时域波形数据
    this.analyser = this.audioContext.createAnalyser();
    this.analyser.fftSize = 2048;

    this.sourceNode.connect(this.analyser);

    // 开始绘制实时波形
    this.drawWave();
  }

  // 持续读取 PCM 数据并绘制到 Canvas
  private drawWave = () => {
    if (!this.analyser) return;

    const canvas = this.canvas;
    const ctx = canvas.getContext('2d');
    if (!ctx) return;

    const bufferLength = this.analyser.fftSize;
    const dataArray = new Uint8Array(bufferLength);

    // 读取当前这一帧的时域数据
    this.analyser.getByteTimeDomainData(dataArray);

    ctx.clearRect(0, 0, canvas.width, canvas.height);
    ctx.lineWidth = 2;
    ctx.strokeStyle = '#1677ff';
    ctx.beginPath();

    const sliceWidth = canvas.width / bufferLength;
    let x = 0;

    for (let i = 0; i < bufferLength; i++) {
      // Uint8Array 的数据范围是 0~255，这里归一化到 0~1
      const v = dataArray[i] / 128.0;
      // 把振幅映射到画布高度
      const y = (v * canvas.height) / 2;

      if (i === 0) {
        ctx.moveTo(x, y);
      } else {
        ctx.lineTo(x, y);
      }

      x += sliceWidth;
    }

    ctx.lineTo(canvas.width, canvas.height / 2);
    ctx.stroke();

    // 下一帧继续绘制，形成实时波形
    this.animationId = requestAnimationFrame(this.drawWave);
  };
}
```

```ts
const canvas = document.getElementById('wave') as HTMLCanvasElement;
```
