# 首屏优化
针对首屏 FCP 和 LCP 指标较差，js 体积过大等问题，我设计了分阶段渲染策略。
首先，将页面拆分为关键路径和非关键路径，首屏只加载核心的总览信息，而将复杂的详情表格通过 defineAsyncComponet 进行按需加载，避免阻塞主要线程。同时，还利用浏览器空闲时间，对后续 Tab 资源进行预加载。
最终显著降低了首屏耗时，FCP 和 LCP 通过浏览器自带的 LightHouse 面板看。


## 1. 概述
定义“关键路径”和“非关键路径”，分阶段渲染
是一个看板类页面，先拆分为关键路径和非关键路径；
关键路径，包含顶部导航、核心总览卡片、主体骨架、最基础数据请求（首屏必要的 1~2 个接口）；
非关键路径（可延后），包含大表格、抽屉/弹窗、图表模块以及非首屏路由页面组件详情页等等。

分阶段渲染设计，第一阶段首屏秒开，只渲染页面结构、筛选等框架，请求渲染核心总览数据，不挂载重表格和图表组件。
第二阶段，使用 React.lazy 和 Suspense 异步加载大表格，发送异步请求等。
第三阶段，使用 requestIdleCallback / scheduler.postTask 预热抽屉、图表组件以及下一个高概率路由页面，在 idle 阶段预取数据 queryClient.prefetchQuery(...)，用户切换 tab/打开抽屉时几乎秒开。

# 权限体系与动态路由
项目里角色存在差异，比如质控员、管理员、科室负责人看到的菜单和可操作按钮都不一样，这里基于 RBAC 做了一套统一的权限控制方案。

具体来说，后端会返回当前用户的角色、权限点和菜单树，前端在拿到这些数据之后，会先把路由表和菜单配置做一次过滤，再基于 `React Router` 的动态路由配置把用户有权限访问的页面注册进系统里。菜单这边我会根据同一份权限树去生成侧边栏配置，保证路由和菜单来源一致，避免出现菜单有入口但路由进不去，或者路由存在但菜单没展示的问题。

在按钮级权限上，把权限点抽成统一的工具函数、`usePermission` 这类自定义 Hook。比如新增、编辑、审核、提交这些操作，会先通过 Hook 读取当前用户的权限点，再决定按钮是否渲染，或者在点击时做二次校验，防止越权操作。


# 语音输入与录音播放器
封装了语音输入和录音播放器模块，主要是为了满足录音质检和病例审核场景下的使用需求。

在录音能力上，主要是基于浏览器原生的 `MediaDevices.getUserMedia` 获取麦克风权限，再结合 `MediaRecorder` 做音频采集和录制状态管理，录制出来的数据会拼成 `Blob`，再转成可下载或者可上传的文件。为了保证录音过程更稳定，我还补了录音开始、暂停、继续、结束、录制时长统计这些状态控制，并且对设备权限被拒、录音中断、页面切后台、浏览器不兼容等异常场景做了兜底处理。

在播放侧，我是用 `Audio` 元素配合进度条状态同步来实现播放器的基础能力，再通过 `requestAnimationFrame` 或定时器去刷新当前播放进度，保证进度条和音频状态同步。波形可视化这块，我会在录音完成后拿到音频数据，再结合 `Web Audio API` 的 `AudioContext` 和 `AnalyserNode` 去解析音频波形，然后用 `Canvas` 或 SVG 把波形绘制出来。倍速播放则是直接通过播放速率 `playbackRate` 来实现，断点续播会把当前播放进度缓存到本地或者页面状态里，用户下次进入时可以自动恢复到上次位置。

录音结束后先通过 AudioContext 解析音频文件，获取 PCM 采样数据。PCM 本质上是一组 -1 到 1 的音量值，我会对数据进行抽样降采样，然后将时间映射到 X 轴、音量映射到 Y 轴，最后使用 Canvas 连线绘制波形。为了避免大文件导致渲染卡顿，实际项目中会对采样点进行压缩，只保留部分关键点进行展示。

Canvas 是浏览器提供的即时绘图 API，本质上是一块画布。相比大量 DOM 节点渲染，Canvas 更适合绘制波形图、图表、游戏等高频图形场景。在录音播放器中，我会先通过 AudioContext 获取 PCM 音频数据，再利用 Canvas 将采样值映射为坐标点，通过 lineTo 连线绘制出音频波形。


useRecorder.ts
```jsx
import { useRef, useState } from "react";

export function useRecorder() {
  const mediaRecorderRef = useRef<MediaRecorder | null>(null);
  const chunksRef = useRef<Blob[]>([]);

  const [recording, setRecording] = useState(false);
  const [paused, setPaused] = useState(false);
  const [audioUrl, setAudioUrl] = useState("");

  // 开始录音
  const start = async () => {
    const stream = await navigator.mediaDevices.getUserMedia({
      audio: true,
    });

    const recorder = new MediaRecorder(stream);

    recorder.ondataavailable = (e) => {
      chunksRef.current.push(e.data);
    };

    recorder.onstop = () => {
      const blob = new Blob(chunksRef.current, {
        type: "audio/webm",
      });

      const url = URL.createObjectURL(blob);

      setAudioUrl(url);

      chunksRef.current = [];
    };

    recorder.start();

    mediaRecorderRef.current = recorder;
    setRecording(true);
  };

  const pause = () => {
    mediaRecorderRef.current?.pause();
    setPaused(true);
  };

  const resume = () => {
    mediaRecorderRef.current?.resume();
    setPaused(false);
  };

  const stop = () => {
    mediaRecorderRef.current?.stop();
    setRecording(false);
    setPaused(false);
  };

  return {
    recording,
    paused,
    audioUrl,
    start,
    pause,
    resume,
    stop,
  };
}
```

页面使用
```jsx
import { useRecorder } from "./useRecorder";

export default function RecorderDemo() {
  const {
    start,
    pause,
    resume,
    stop,
    recording,
    paused,
    audioUrl,
  } = useRecorder();

  return (
    <div>
      <button onClick={start}>开始录音</button>

      {recording && !paused && (
        <button onClick={pause}>暂停</button>
      )}

      {paused && (
        <button onClick={resume}>继续</button>
      )}

      <button onClick={stop}>结束录音</button>

      {audioUrl && (
        <audio controls src={audioUrl} />
      )}
    </div>
  );
}
```

波形图
```jsx
/**
 * 波形图绘制
 * 1. 录音结束后，把 Blob 转成 ArrayBuffer
 * 2. 使用 AudioContext 解析音频数据
 * 3. 从音频通道中拿到 PCM 采样值
 * 4. 将采样值按间隔抽样后绘制到 Canvas 上
 */
const drawWaveform = async (blob, canvasRef) => {
  // 1. 创建音频上下文，用于解析音频文件
  const audioContext = new AudioContext();

  // 2. Blob 转 ArrayBuffer，供 decodeAudioData 使用
  const arrayBuffer = await blob.arrayBuffer();

  // 3. 将音频文件解码成 AudioBuffer
  const audioBuffer = await audioContext.decodeAudioData(arrayBuffer);

  // 4. 获取单声道的 PCM 数据（真实项目中可根据需要合并左右声道）
  const channelData = audioBuffer.getChannelData(0);

  // 5. 获取 Canvas 画布上下文
  const canvas = canvasRef.current;
  if (!canvas) return;

  const ctx = canvas.getContext('2d');
  if (!ctx) return;

  // 6. 清空画布，避免重复绘制
  ctx.clearRect(0, 0, canvas.width, canvas.height);

  // 7. 设置绘制样式
  ctx.beginPath();
  ctx.strokeStyle = '#4f46e5';
  ctx.lineWidth = 1.5;

  // 8. 按固定间隔抽样绘制波形
  const step = 100;
  const middleY = canvas.height / 2;
  const scaleY = 50;

  for (let i = 0; i < channelData.length; i += step) {
    // PCM 值范围是 -1 ~ 1，这里乘以缩放系数映射到画布高度
    const value = channelData[i] * scaleY;
    const x = i / step;
    const y = middleY + value;

    // 首个点用 moveTo，后续点用 lineTo 连线
    if (i === 0) {
      ctx.moveTo(x, y);
    } else {
      ctx.lineTo(x, y);
    }
  }

  // 9. 完成路径绘制
  ctx.stroke();

  // 10. 释放音频上下文资源，避免占用过多内存
  await audioContext.close();
};
```



# 列表页性能与交互优化
在列表页这块，我也做过一些比较细的优化。因为质控和教学平台里很多页面都是“筛选条件 + 表格 + 详情抽屉”的结构，如果不做处理，页面很容易出现首次渲染重、切换条件慢、频繁请求的问题。

所以我会优先控制列表页的渲染粒度，比如把筛选区、表格区、详情区拆开管理，确保筛选项变更不会导致不必要的整页刷新；另外在请求层面，我也会对高频切换的条件做防抖或者节流处理，避免用户连续操作时接口被重复触发。对于分页、排序和回显这类交互，我也会尽量保持状态一致，保证用户切换回来时页面还是之前的上下文，不需要重新设置。
