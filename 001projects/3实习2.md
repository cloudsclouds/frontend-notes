# Radix UI + Tailwind CSS
Radix UI 是一个专注于可访问性和交互逻辑的无样式 React 组件库。
它提供了像对话框、下拉菜单、标签页等常见组件的底层功能，比如键盘导航、焦点管理这些无障碍特性，处理好了组件的交互逻辑，但不自带样式，需要结合 Tailwind 的原子类快速拼接样式，比手写 CSS 更快，还能避免样式冲突。

Tailwind CSS 是原子化 CSS 框架，特点是把 CSS 属性拆成小类名，比如 “flex”“mt-4”“text-blue-500”，直接在 HTML 标签里组合类名就能写样式，不用单独写 CSS 文件。
和普通 CSS 比，它不用费心取类名，开发速度快，而且样式不会冗余，因为类名是复用的。普通 CSS 需要定义类名，写具体属性，大型项目容易出现样式冲突或冗余代码。

# 首屏优化
针对用户首次加载时间页面过长，发现首屏 FCP 和 LCP 指标较差、js 体积过大等问题，我设计了分阶段渲染策略。
首先，将页面拆分为关键路径和非关键路径，首屏只加载核心的总览信息，而将复杂的详情表格通过 React.lazy 和 Suspense 进行按需加载，结合 Vite 自动分包机制，避免阻塞主要线程。同时，还利用浏览器空闲时间，对后续 Tab 资源进行预加载。
最终显著降低了首屏耗时，FCP 和 LCP 通过浏览器自带的 LightHouse 面板看。

## Q1: 概述
是一个看板类页面，先拆分为关键路径和非关键路径；
关键路径，包含顶部导航、核心总览卡片、主体骨架、最基础数据请求（首屏必要的 1~2 个接口）；
非关键路径（可延后），包含大表格、抽屉/弹窗、图表模块以及非首屏路由页面组件详情页等等。

分阶段渲染设计，第一阶段首屏秒开，只渲染页面结构、筛选等框架，请求渲染核心总览数据，不挂载重表格和图表组件。
第二阶段，使用 React.lazy 和 Suspense 异步加载大表格，发送异步请求等。
第三阶段，使用 requestIdleCallback / scheduler.postTask 预热抽屉、图表组件以及下一个高概率路由页面，在 idle 阶段预取数据 queryClient.prefetchQuery(...)，用户切换 tab/打开抽屉时几乎秒开。

# 权限体系与动态路由
项目里角色存在差异，比如质控员、管理员、科室负责人看到的菜单和可操作按钮都不一样，这里基于 RBAC 做了一套统一的权限控制方案。

具体来说，后端会返回当前用户的角色、权限树，权限树里有页面权限和按钮权限点。前端在拿到这些数据之后，会先把路由表和菜单配置做一次过滤，再基于 `React Router` 的动态路由配置把用户有权限访问的页面注册进系统里。菜单这边我会根据同一份权限树去生成侧边栏配置，保证路由和菜单来源一致。

在按钮级权限上，把按钮权限点抽成统一的工具函数 `usePermission` 这类自定义 Hook。比如新增、编辑、审核、提交这些操作，会先通过 Hook 读取当前用户的权限点，再决定按钮是否渲染；在点击时做二次校验，防止越权操作。


# 病例质控审核
负责评分组件开发。这个组件要支持质控员对病例录音的人工审核评分，不同题的评分规则不一样，题型涵盖单选、多选、等级评分等。我设计了 “外层容器 + 子组件” 的结构：
外层容器主要负责一些通用逻辑，比如后端规则转前端结构、总分计算、处理只读和编辑状态切换，是否需要回填历史记录；
内层再根据配置动态分发不同的评分子组件，比如单选、多选、等级评分都各自封装。
这样做的好处是，后面如果评分规则有调整，或者新增一种题型，优先改配置和局部组件就可以，不需要整块页面重复开发，复用性和可维护性会更好。
另外在复核场景下，复核员需要参考前两轮质控员的评分结果，我也补了对应的查看和切换能力，方便在复核时对照不同人的评分记录。

## 1. “外层容器 + 子组件”，具体是怎么分工的？

外层容器主要负责三件事。
- 第一是把后端返回的规则数据转换成前端统一结构，比如统一成 rule id、maxScore、selectionMode、checkpoints 这些字段。
- 第二是统一管理状态和分数，比如每一题当前得分、总分、只读态还是编辑态、是否需要回填历史记录。
- 第三是根据配置决定渲染哪一种子组件，比如 single 渲染单选卡片，multiple 渲染多选卡片，level 渲染等级评分卡片。
- 子组件本身只关心自己的交互，不关心整张评分卡怎么汇总。

容器给子组件入参：标准化后的单题配置（题型、满分、评分规则）、历史回填值、禁用只读状态；
子组件对外出参：分值变更回调，只抛出当前题 ID、单题得分、用户选择数据。

## 2. 后端规则和前端结构是怎么映射的？
后端给的规则本身更偏业务定义，比如一个模块下面有哪些子项、每个子项是什么评分方式、检查点有哪些、每个检查点扣多少分。
前端直接使用这套结构会比较散，所以我做了一层映射，把它整理成统一的 rules 配置。
比如每条规则都会统一成：题目 id、标题、满分、评分模式、检查点列表、等级分档这些字段。
这样前端渲染时就不需要到处判断原始接口结构，而是只认这一层转换后的数据。

## 3. 总分是怎么计算的？
总分不是让每个子组件各算各的，而是由外层统一汇总。
每个子组件只负责把当前题目的得分变化抛出来，比如单选题选中某个扣分项后返回当前题得分，多选题根据多个检查点的扣分结果返回当前题得分，等级评分直接返回选中的档位分值。
外层拿到每题当前分之后，按规则列表统一求和，得到整张评分卡总分。

## 4. 这里面你觉得最难的点是什么？
我觉得最难的点不是把 UI 画出来，而是把规则差异收敛成统一结构。
因为题型不同、扣分方式不同、还有编辑态、只读态、历史回填、复核参考这些场景，如果一开始抽象不好，后面组件会越来越乱。
所以后来我比较强调两件事：第一是统一数据结构，第二是统一父子组件之间的输入输出接口。这个抽象做好之后，后续扩展会顺很多。

# 语音输入与录音播放器
封装了语音输入和录音播放器模块，主要是为了满足录音质检和病例审核场景下的使用需求。

在录音采集上，主要是基于浏览器原生 `getUserMedia` 获取麦克风权限，拿到音频流后，再创建 `MediaRecorder` 实例，设置合适的音频格式，调用 `start` 方法开始录制。录制过程中，`MediaRecorder` 会监听 `dataavailable` 事件接收分片音频数据，拼成 `Blob` 对象。最后把 `Blob` 转成 `File` 对象用于上传或下载。

在波形可视化上，主要是基于原生 `WebAudio` 和 `Canvas` 方案。
录制实时波形：借助 `AudioContext` 解析麦克风实时流，提取 `PCM` 采样数据，由 `Canvas` 动态绘制波形；结合质检规则自定义渲染：爆音片段标红、静音片段标灰，支持局部缩放查看异常波形，可录制中实时标注问题音频。
播放静态波形：播放前解码音频文件得到完整 PCM 数据，基于 Canvas 渲染全量波形图谱。

在播放器基础能力上，主要是基于原生 `Audio` 标签搭建播放器基础，借助 `requestAnimationFrame` 循环刷新播放时间，联动进度条实现进度实时同步。  
倍速播放：修改 `playbackRate` 参数控制播放倍率；
断点续播：缓存当前播放时间戳至页面状态 / 本地存储，再次打开自动跳转上次播放点位；

## Q1: 你是怎么实现录音波形可视化的？

录音结束后先通过 AudioContext 解析音频文件，获取 PCM 采样数据。PCM 本质上是一组 -1 到 1 的音量值，我会对数据进行抽样降采样，然后将时间映射到 X 轴、音量映射到 Y 轴，最后使用 Canvas 连线绘制波形。为了避免大文件导致渲染卡顿，实际项目中会对采样点进行压缩，只保留部分关键点进行展示。

## Q2: Canvas 是怎么绘制波形图的？

Canvas 是浏览器提供的即时绘图 API，本质上是一块画布。相比大量 DOM 节点渲染，Canvas 更适合绘制波形图、图表、游戏等高频图形场景。在录音播放器中，我会先通过 AudioContext 获取 PCM 音频数据，再利用 Canvas 将采样值映射为坐标点，通过 lineTo 连线绘制出音频波形。

```ts
class AudioRecorderPlayer {
  private mediaStream: MediaStream | null = null;
  private mediaRecorder: MediaRecorder | null = null;
  private audioChunks: Blob[] = [];
  private audioUrl = '';
  private audio = new Audio();

  private audioContext: AudioContext | null = null;
  private analyser: AnalyserNode | null = null;
  private sourceNode: MediaStreamAudioSourceNode | null = null;
  private animationId = 0;

  constructor(private canvas: HTMLCanvasElement) {}

  // 1. 开始录音：申请麦克风权限，初始化 MediaRecorder 和波形分析器
  async startRecord() {
    // 获取麦克风音频流
    this.mediaStream = await navigator.mediaDevices.getUserMedia({ audio: true });

    // 创建录音器，浏览器会持续产出音频分片
    this.mediaRecorder = new MediaRecorder(this.mediaStream, {
      mimeType: 'audio/webm'
    });

    // 每次开始录音前都清空旧分片，避免串音
    this.audioChunks = [];

    // 录音分片回调：把每次产出的数据先缓存起来
    this.mediaRecorder.ondataavailable = (event) => {
      if (event.data.size > 0) {
        this.audioChunks.push(event.data);
      }
    };

    // 初始化实时波形分析
    this.initWaveAnalyzer(this.mediaStream);

    // 开始录音
    this.mediaRecorder.start();
  }

  // 2. 停止录音：拼接 Blob，转成可播放的 url，并清理录音流
  stopRecord(): Promise<File> {
    return new Promise((resolve, reject) => {
      if (!this.mediaRecorder) {
        reject(new Error('录音器未初始化'));
        return;
      }

      this.mediaRecorder.onstop = () => {
        // 把所有分片拼成一个完整音频文件
        const audioBlob = new Blob(this.audioChunks, { type: 'audio/webm' });

        // 给播放器使用的本地预览地址
        this.audioUrl = URL.createObjectURL(audioBlob);
        this.audio.src = this.audioUrl;

        // 转成 File，方便后续上传到服务端
        const file = new File([audioBlob], `record-${Date.now()}.webm`, {
          type: 'audio/webm'
        });

        // 停掉麦克风采集，释放设备占用
        this.mediaStream?.getTracks().forEach((track) => track.stop());

        // 停掉波形动画
        cancelAnimationFrame(this.animationId);

        resolve(file);
      };

      this.mediaRecorder.stop();
    });
  }

  // 3. 播放录音：直接复用原生 Audio 能力
  play() {
    if (!this.audioUrl) return;
    this.audio.play();
  }

  pause() {
    this.audio.pause();
  }

  // 4. 倍速播放：直接修改 playbackRate
  setPlaybackRate(rate: number) {
    this.audio.playbackRate = rate;
  }

  // 5. 断点续播：把当前播放时间保存起来，下次恢复
  saveProgress() {
    localStorage.setItem('record-progress', String(this.audio.currentTime));
  }

  restoreProgress() {
    const saved = localStorage.getItem('record-progress');
    if (saved) {
      this.audio.currentTime = Number(saved);
    }
  }

  // 初始化实时波形分析
  private initWaveAnalyzer(stream: MediaStream) {
    this.audioContext = new AudioContext();

    // 把麦克风流接入 Web Audio
    this.sourceNode = this.audioContext.createMediaStreamSource(stream);

    // AnalyserNode 用来提取时域波形数据
    this.analyser = this.audioContext.createAnalyser();
    this.analyser.fftSize = 2048;

    this.sourceNode.connect(this.analyser);

    // 开始绘制实时波形
    this.drawWave();
  }

  // 持续读取 PCM 数据并绘制到 Canvas
  private drawWave = () => {
    if (!this.analyser) return;

    const canvas = this.canvas;
    const ctx = canvas.getContext('2d');
    if (!ctx) return;

    const bufferLength = this.analyser.fftSize;
    const dataArray = new Uint8Array(bufferLength);

    // 读取当前这一帧的时域数据
    this.analyser.getByteTimeDomainData(dataArray);

    ctx.clearRect(0, 0, canvas.width, canvas.height);
    ctx.lineWidth = 2;
    ctx.strokeStyle = '#1677ff';
    ctx.beginPath();

    const sliceWidth = canvas.width / bufferLength;
    let x = 0;

    for (let i = 0; i < bufferLength; i++) {
      // Uint8Array 的数据范围是 0~255，这里归一化到 0~1
      const v = dataArray[i] / 128.0;
      // 把振幅映射到画布高度
      const y = (v * canvas.height) / 2;

      if (i === 0) {
        ctx.moveTo(x, y);
      } else {
        ctx.lineTo(x, y);
      }

      x += sliceWidth;
    }

    ctx.lineTo(canvas.width, canvas.height / 2);
    ctx.stroke();

    // 下一帧继续绘制，形成实时波形
    this.animationId = requestAnimationFrame(this.drawWave);
  };
}
```

```ts
const canvas = document.getElementById('wave') as HTMLCanvasElement;
```
